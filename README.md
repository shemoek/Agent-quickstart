# 一、Agent 是什么，躯体和大脑的区别
手机上和网页端用的大语言模型（ChatGPT、DeepSeek、Kimi 等），是一个"只能聊天的大脑"，它能听懂你的话、回答问题、给建议，但它**没有手**，不能帮你改文件、运行代码、生成 PDF。

Agent（智能体）则是把"大脑"放进一个"躯体"里。这个躯体可以：

+ 读写你电脑上的文件
+ 执行终端命令
+ 调用外部工具（搜索网页、解析 PDF、生成图片等）

所以 Agent = 大模型（大脑）+ 工具调用能力（躯体）。有了 Agent，不只是问 AI 问题，而是让 AI**直接帮你干活**。

国内的 Agent 起步晚，**Claude Code 和 Codex** 是最主流最强的两个。两者各有优势：

+ **Claude Code**：代码编辑更精准，自由度更高，社区有大量配置方案和中文教程，更深入使用
+ **Codex**：安装方便（Windows 自带 Microsoft Store 搜索即装），用户端成熟，使用体验好，安全策略完善

除此之外，还有一些社区项目如 **OpenClaw、Hermes** 等，也都有各自的优势。

但是Claude Code 默认使用 Anthropic 自家的 Claude 模型，Codex 默认使用 OpenAI 自家的 ChatGPT。

**国外模型使用还普遍有三个问题：**

1. 注册常需要海外手机号和信用卡
2. 价格极高，花费是国内模型的几十到上百倍
3. 部分厂商反华，或者对国内使用有限制

所以流行的方法是：**用国外开发的优秀 Agent 外壳，接入国内性价比高的大模型**。

## 3. API 是什么、怎么获取
| 概念 | 通俗解释 |
| --- | --- |
| **API Key** | 一串密钥，等同于你在大模型厂商那里的"充值账户密码"。Agent 用它来调用模型服务 |
| **联网服务 API**（如 Tavily） | 单独注册的搜索引擎 API，让 Agent 可以上网搜索 |
| **文档解析 API**（如 E2B Code Interpreter） | 让 Agent 运行 Python 代码的能力，解析 Excel、PDF 等 |


**以 DeepSeek 为例获取 API Key 的完整流程**：

1. 打开 DeepSeek 官网（[https://platform.deepseek.com](https://platform.deepseek.com)）
2. 注册账号（手机号即可）
3. 点击"充值"——微信/支付宝扫码，建议先充 **30-50 元**（见第八篇的费用建议）
4. 在控制台左侧找到"API Keys"，点击"创建 API Key"
5. 输入名称（随意），点击创建，立即复制保存

> ⚠️ API Key 只会显示一次！务必立即粘贴到安全的地方（比如密码管理器或加密笔记）。
>

## 4. 为什么不建议用"中转站"
市面上有不少提供"一站式 API"的第三方平台（俗称中转站），声称整合多家模型、统一计费。**建议远离**，原因：

+ 模型冒充：用便宜模型充高价模型，你不知道背后实际在跑什么
+ 不稳定：频繁封禁、限流，随时跑路
+ 价格虚高：中间商赚差价

直接去模型官方平台充值 API，贵不了多少但稳得多。

## 4. VSCode —— 最强大的 AI 辅助编辑器

+ 本体轻量（类似加强版记事本），但插件生态极强

4. 搜索安装你要用的 Agent 插件（如 Claude Code 或 Codex）

**VSCode + LaTeX 学术写作方案：**

Overleaf 是好用的在线 LaTeX 平台，有全球最全的论文 / Beamer / 书籍模板，很多国内大学也上传了自己的学位论文模板。但 Overleaf 免费版编译有超时限制——论文写长了编译就报错，逼你充会员。

最佳方案：

1. 去 Overleaf 上找到你学校或领域的好用模板，下载到本地
2. 在电脑上安装 TeX 发行版（Windows 推荐 MiKTeX：[https://miktex.org](https://miktex.org) 或 TeX Live）
3. 在 VSCode 扩展广场搜索安装 **LaTeX Workshop** 插件
4. 打开本地 .tex 文件，Ctrl+Alt+B 即可实时编译为 PDF

最终效果：VSCode 页面干净、本地编译无限制、还能用 AI 插件辅助写论文，比 Overleaf 网页端高效得多。

# 四、接入篇：把国内模型接入 Agent
这是整个流程的**核心操作**。目标：让 Claude Code / Codex 不再使用昂贵的国外模型，而是调用你充值好的国内模型 API。

## 1. CCSwitch —— 中间切换工具
**CCSwitch** 是目前最常用、功能最全的代理切换工具，可以让 Claude Code 透明地使用任意兼容的 API。

+ GitHub 地址：[https://github.com/ccswitch/ccswitch](https://github.com/ccswitch/ccswitch)（以实际项目 README 为准）
+ 安装后只需在配置界面选择"供应商"、粘贴 API Key 即可
+ 支持模型选择、API 地址自定义、Agent 版本更新检测等功能

同类工具：Codex+ 等也有类似功能，但 CCSwitch 用户最多、教程最丰富。

## 2. 实操流程：从零到运行
**第 1 步：装 Node.js**  
如前所述，[https://nodejs.org](https://nodejs.org) 下载 LTS 版安装。

**第 2 步：装 Agent**

+ 零基础用户：Microsoft Store 搜索 Codex 安装（最简单）
+ 有基础用户：打开终端（Win+R → 输入 `cmd`），输入：

```plain
npm install -g @anthropic-ai/claude-code
```

**第 3 步：获取 API Key**  
去 [https://platform.deepseek.com](https://platform.deepseek.com) 注册、充值 30-50 元、创建并复制 API Key。

**第 4 步：安装并配置 CCSwitch**  
去 CCSwitch GitHub 页面下载最新版本，按引导安装。打开 CCSwitch，在"供应商"下拉中选择 "DeepSeek"，粘贴 API Key，选择模型（推荐 `deepseek-chat` 或 `deepseek-reasoner`），保存。

**第 5 步：启动 Agent，开始干活**  
终端输入 `claude`（Claude Code）或点击 Codex 图标，Agent 就会通过 CCSwitch 调用 DeepSeek。可以在 Agent 里直接发指令测试——比如让它"在当前目录创建一个 readme.md"。

## 3. Chatbox —— 在接入 Agent 前先验证 API
**Chatbox** 是大模型的通用桌面客户端，支持 Windows / macOS / Linux。

官网：[https://chatboxai.app](https://chatboxai.app)

**为什么要先用 Chatbox？**

+ 各大厂商的官方网页端往往有严格的敏感词过滤和各种限制
+ Chatbox 直接用 API 对话，更自由、质量更高，而且你可以自行调整"创意度"参数
+ 在把 API Key 配给 Agent 之前，先用 Chatbox 测一下——API 通不通？模型响应正常吗？

使用 Chatbox 时，建议把"创意度 / Temperature"调到 **0.25 或以下**。除非你在写小说，否则 AI 作为生产力工具，稳定可靠比花样百出重要得多。

Chatbox 还支持：

+ **Tavily**（联网搜索，注册简单，[https://tavily.com](https://tavily.com)）
+ **E2B Code Interpreter**（代码执行/文档解析，[https://e2b.dev](https://e2b.dev)）

这两个服务注册账号都很容易，可以大幅增强 AI 能力。注意：手机上也能配 Tavily 联网功能，但 MCP 相关功能目前只有桌面端支持。

# 五、进阶篇：Skill 与 MCP
这是 Agent 从"能用"到"好用"的关键，相当于给 Agent 装上"专业工具"。

## 1. Skill 是什么
Skill 是一组**预定义的指令和工具集合**，让 Agent 在特定领域表现更专业。比如"PDF 处理" Skill 会给 Agent 提供一套 PDF 读取、合并、表单填写的工作流程。

常用的 Skill 及场景：

| Skill | 用途 |
| --- | --- |
| **pdf** | 读取、合并、拆分、填写 PDF 表单 |
| **xlsx** | 创建、编辑、分析 Excel 表格 |
| **pptx** | 创建和编辑 PPT 幻灯片 |
| **imagegen** | 按需求生成或编辑图片 |
| **debug** | 系统化排查 Bug 和报错 |


Skill 的安装：在 Codex 中通过 `skill-installer` 浏览和安装，或直接把 Skill 目录放到指定位置。

## 2. MCP（Model Context Protocol）是什么
MCP 是一套**开放协议**，让大模型可以调用外部服务和数据源——可以理解为 Agent 的"USB 接口"。

常用的 MCP 服务：

| MCP 服务 | 用途 |
| --- | --- |
| **Tavily** | 联网实时搜索 |
| **E2B Code Interpreter** | 在沙盒中执行 Python 代码，处理数据分析、文件解析 |
| **Filesystem** | 让 Agent 安全读写本地文件 |
| **GitHub** | 操作仓库、提 Issue、查 PR |
| **Puppeteer / Browser** | 控制浏览器，抓取网页、自动化表单填写 |


大多数 MCP 服务通过 JSON 配置文件接入，一般放到 Agent 的配置目录下即可。配置难度不高，参考各家文档 10 分钟内搞定。

**建议**：初期不用追求装太多，Skill 和 MCP 各选 3-5 个最常用的就完全够用。贪多反而会让 Agent 的上下文混乱。

# 六、技巧篇：高效使用心法
以下是我从大量实践中总结的几条核心经验——这些比"选哪个模型"更影响实际效率。

## 1. 模块化 + 自己先做 10%-20%
不要把一个大任务直接丢给 AI 说"帮我做完"。正确做法：

1. 把任务拆成模块：先建好文件夹结构，写好每个文件的命名规范
2. 自己先把每个要点的**框架搭好**（比如先写标题层级、占位注释、关键约束条件）
3. 再让 AI 在已有框架内填充和优化

为什么要这样做？

+ AI 不清楚你的审美和习惯。你先把规则定好（风格、格式、范围），AI 在你的框架里填充，结果才不会偏离预期
+ 减少"AI 误解需求 → 返工"的循环，节省大量 API 费用

## 2. 每次任务单独建一个 MD 文档
每次启动一个新任务，第一时间新建一个 Markdown 文档（别忘了写日期），记录：

+ 任务目标
+ 具体需求和约束
+ AI 的每一步操作和输出摘要
+ 踩过的坑和最终解决方案

这东西有三个好处：

+ **方便溯源**：一天后你就忘了 AI 到底改了什么
+ **方便模块化喂给其他 AI**：下次做类似任务，直接把这份文档丢给 AI 当上下文
+ **方便人工查看**：MD 格式任何编辑器都能打开，不依赖特定平台

## 3. 新对话窗口往往更"聪明"
AI 对话窗口的"智商"很大程度上取决于**上下文是否干净**。一条满了杂七杂八历史记录的对话，AI 会越来越笨——因为它不知道该优先关注什么。

**子母模块策略**：

+ **母窗口**：保留核心目标、项目规范、关键约束（约 10-20% 的上下文空间）
+ **子窗口**：把对上下文要求低的小任务分出去单独做，做完把结果反向喂给母窗口

每次重大任务开始时，建议**全新开窗口**，不要复用旧对话。

## 4. AGENTS.md 的妙用
在项目根目录创建一个 `AGENTS.md` 文件，写入：

+ 代码风格规范
+ 项目结构说明
+ 你常用的命令和工具
+ 给 AI 的注意事项

Agent（尤其是 Codex）会自动读取这个文件，并用里面的规则约束自己的行为。这比你每次对话都重复"请用这种方式写代码"高效得多。

# 七、移动篇：离开电脑也能使用
有时你在外面，只有手机，但任务需要继续和 Agent 交互。怎么办？

## 三种主流方案
| 方案 | 配置难度 | 功能完整度 | 网络要求 | 推荐度 |
| --- | --- | --- | --- | --- |
| **飞书机器人** | ⭐⭐ 中等 | 中等（文字交互为主） | 无需翻墙 | ⭐⭐⭐ |
| **微信机器人** | ⭐⭐⭐ 较高 | 较低（微信 API 限制多） | 无需翻墙 | ⭐⭐ |
| **Telegram Bot** | ⭐ 低（但有门槛） | ⭐⭐⭐ 最高 | 需科学上网 | ⭐ |


## 各方案简评
**飞书机器人**：依托飞书的开放平台，可以用 webhook 把 Agent 消息转发到手机。适合在校学生（很多高校用飞书办公），配置一次后长期可用。

**微信机器人**：看起来最方便，但微信对第三方机器人限制严格，配置不稳定，容易封号。不推荐作为主力方案。

**Telegram Bot**：功能最完整，可以实现和桌面端几乎一样的交互体验。但：

+ 需要科学上网才能使用 Telegram
+ 注册需要手机号（建议用虚拟号码）
+ Telegram 上不良信息较多，容易分心

**总体建议**：日常使用首选飞书，Telegram 作为高级备选，微信不推荐。

# 八、费用篇：省钱与防翻车
这是最后但非常重要的一篇——不控制好费用，Agent 可能让你"钱不是问题，问题是没钱"。

## 1. API 是怎么计费的
大模型 API 按 **token** 计费。token 不是"一个字"，而是模型内部处理文本的最小单位。粗略换算：

+ 1 个中文字 ≈ 1.5-2 个 token
+ 1 个英文单词 ≈ 1-1.3 个 token

计费分两部分：**输入 token**（你发给 AI 的内容 + 上下文历史）+ **输出 token**（AI 回复的内容）。输出通常比输入贵 2-4 倍。

## 2. 日常费用估算
| 使用强度 | 典型日消耗 | 月费（以 DeepSeek V3 为例，约 ¥2/百万输出 token） |
| --- | --- | --- |
| 轻度（偶尔问问题、改几行代码） | 约 5 万 token | 约 ¥3-5 |
| 中度（每天写文档、改代码、分析数据） | 约 30 万 token | 约 ¥15-25 |
| 重度（全天高频使用、处理长文、大量代码生成） | 约 100 万 token | 约 ¥50-80 |


选 GLM 可再便宜 50%-80%，选 DeepSeek 则能力更强但稍贵。总体而言，国内模型即使重度使用，月费也远低于一杯咖啡的成本。

## 3. 充值策略：每次 30-50 元
不要一次性充太多。原因只有一个：**AI 偶尔会"发疯"**。

什么叫"发疯"？你给 AI 一个任务，它可能理解偏了方向，开始循环执行、反复生成代码、大量读取文件——不知不觉几百块钱就烧没了。

**应对方法**：

+ 单次充值 **30-50 元**，用完再充
+ 留意 API 平台的后台用量监控（DeepSeek 等平台都有实时用量面板）
+ 如果看到 token 消耗异常飙升，立即在平台上暂时禁用该 API Key
+ 给 Agent 的任务描述尽量**明确边界**，比如"只修改这一个文件"而非"帮我优化所有代码"
